# export-models — reproducible ONNX export of the semantic search models

This tool runs **outside** IPED. It turns the pinned upstream models into self-contained ONNX files
that take raw input and return an L2-normalised embedding. The text tokenizer runs **inside** the
graph (ONNX Runtime Extensions), so the file that prepares a case during processing, the file that
embeds a question in the analysis UI and the file the reference remote server serves are the same
file, byte for byte.

Nothing here is part of the IPED release. The release consumes the zip this tool produces.

## Text model

| | |
|---|---|
| Upstream | [`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small) at revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`, file `onnx/model.onnx` |
| License | MIT (declared in the model card) |
| Identity | `intfloat/multilingual-e5-small@614241f622f53c4eeff9890bdc4f31cfecc418b3+onnx-int8-ortx` |
| `model.onnx` sha256 | `7265207efcd46ef6a8c852f3354183a8f47b8b494d6800f9590f6786d5a6ae88` (produced twice on 2026-09-26, identical) |
| Size | 123 MB (`model.onnx`), 88 MB zipped |
| Input / output | `text`: string `[N]` (prefix already applied) → `embedding`: float `[N, 384]`, unit norm |

What the graph does, in order:

1. `SentencepieceTokenizer` (domain `ai.onnx.contrib`), generated by `gen_processing_models` from
   the upstream tokenizer. Emits XLM-RoBERTa ids with `<s>` and `</s>`.
2. Padding glue in standard opset-11 operators: ragged ids to `input_ids` / `attention_mask` /
   `token_type_ids` `[N, L]`. Rows above 512 tokens keep their first 511 ids and end in `</s>`,
   exactly as the reference tokenizer truncates.
3. The upstream encoder, quantized: dynamic int8, **unsigned weights (U8U8), per output channel**.
   U8U8 keeps the integer matmuls exact on CPUs without VNNI, where U8S8 can saturate.
4. Masked mean pooling and L2 normalisation (the e5 recipe).

The prefixes `query: ` and `passage: ` are **not** applied by the graph. They are recorded in
`model.json`, and IPED applies them by role (question or passage).

Verification done by the export itself (recorded in `model.json` → `export.verification`):

- The in-graph ids and attention mask are **identical** to the reference tokenizer's
  (`truncation=True, max_length=512`), for texts in PT, EN and ES, the empty string and a text well
  above 512 tokens. The export fails if they differ.
- Cosine between the int8 embedding and the fp32 reference: 0.9965–0.9974 on natural text, 0.983 on
  the empty string, 0.950 on the synthetic 900-word repetition. Quantization variants compared on
  2026-09-26: per-tensor U8 0.988–0.996, per-tensor S8 0.986–0.993, MatMul-only (407 MB) no better
  than per-channel.

### Running it

```powershell
# Python 3.11 in any isolated environment
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python export_models.py text --out <dir>
```

Output:

```text
<dir>/models/semantic/text/multilingual-e5-small-int8/
├── model.onnx
├── model.json      # identity, sha256, dimensions, similarity, prefixes, probesVersion, versions
└── LICENSE
<dir>/semantic-text-multilingual-e5-small-int8.zip   # the model folder at the zip root, deterministic
```

Downloads from Hugging Face happen here, in the export, and never in IPED.

### Installing the zip for the IPED build

The release unpacks the zip into `models/semantic/text/` through the
`unpack-semantic-text-model` execution in `iped-app/pom.xml`, the same mechanism as the Vosk
models. Publishing the artifact in the IPED Maven repository is a maintainer action. Until it is
published, install it in the local repository:

```powershell
mvn install:install-file -Dfile=<dir>\semantic-text-multilingual-e5-small-int8.zip `
    -DgroupId=iped.semantic.models -DartifactId=multilingual-e5-small-int8 `
    -Dversion=1.0 -Dpackaging=zip
```

Without the artifact the build still works: the execution is skipped, and the text modality then
reports "local model missing" at start-up (FR-042) instead of preparing anything.
